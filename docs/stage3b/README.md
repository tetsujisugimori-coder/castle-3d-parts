## 設計上の区分

原資料は既存SRC-0001の部分照合済み記録、HYP-0001の帰属仮説、前工程の研究境界を参照した。これらから木戸の軸受形式・寸法・年代を確定できない。新たに同時代実物を実見したとは主張しない。

支持機構の歴史的候補は未確定のC、検証用形状・隙間・部材構成はDとする。現代金属蝶番を歴史的標準として採用しない。`research-boundary.json` に参照・判断・未確認を分けて保存する。

## 検証計画

1. CADで支持部、回転軸、葉との結合、角度範囲を定義し、既存7部材の3姿勢一致を検証する。
2. CAD保存・再読込、寸法/角度変更と復帰、実STEP書出し/再読込、Blender保存/再読込、GLB保存/再読込をそれぞれ記録する。
3. 全可動部と固定部・木柵・基準面を対象に、距離・実形状の交差体積を計測する。意図した接触/締結と不正な貫通をペアごとに区別する。単なるBBox重なりを最終判定にしない。
4. 1°以下の標本検査は標本に限る。全経路の主張には独立した包絡形状または誤差上界を必要とする。未証明区間をUNKNOWNとする。
5. 軸ずれ、欠損支持、ID違い、隙間不足、範囲外角度、形式変換ずれ等の反例で誤PASSを検出する。
6. 候補Webで角度・再生/停止・反転・軌跡/軸・図面選択・木柵接続を検査。Chromium/WebKit×375/390/765/1280×通常/reduced motion。未実施を成功扱いしない。
7. 最終HEADとCI tree、原artifact、独立レビューを照合して限定受入を判定する。

## 制約

機構試作Dの幾何・変換・表示の検査である。力学的荷重支持、実際の摩擦・変形、締結強度、施工、耐久、史実の妥当性を立証しない。FreeCAD Qt offscreen/Blender backgroundの実行と、人によるGUI操作を区別する。実機iPhone Safari、物理入力、手動GUIは実施記録がない限りNOT_TESTED。

本番Pagesワークフローは保全する。今回も候補ビルダーとDraft PRで提出し、マージ/本番公開は別判断。

## 実装した機構と操作範囲

原7部材に、上下スピンドル2、上下軸受2、上下連結材2、閉鎖/開放ストッパー2を追加し、計15部材とした。下部軸受にはスピンドル端面を受ける座を設けた。軸半径12mm、軸受穴半径12.5mm、径方向隙間0.5mmは試作値である。

連結材と軸の円筒面接触、および連結材と扉の面接触は理想的な剛結として扱う。接触していることだけでトルク伝達・摩擦・実際の軸受機能・荷重支持が立証されたとはしない。接触面積の記録は `native-tests.json` にあり、強度を表す値ではない。

CADの `Mechanism.Angle` を基準として、可動親階層 `GatePivot` と6可動部材をGLBへ引き継ぐ。姿勢は毎回基準形状から角度指定するため、増分変換を重ねて位置をずらさない。標準範囲0°〜90°で旧0/45/90°の7部材とBRep形状差を照合した。

ストッパーはMinimumAngle/MaximumAngleに連動する。10°〜60°へ変更し、35°で保存再読込した別原本 `range-variation.FCStd` を保全した。両端で扉と該当ストッパーの間隔0・交差体積0を確認した。標準Web成果は0°〜90°に固定し、変更版の検証を標準版以外の全設定へ拡張しない。他寸法変更は再生成・再検証を要し、単なるメタデータ変更を検証済み形状と扱わない。

## 実際に行ったネイティブ検査

- FreeCAD1.0のQt offscreen実行、FCStd保存再読込、STEP書出しと再読込。手動GUIではない。
- 上下支持と連結を含む15部材のBRep。旧3姿勢の7部材を別の旧原本と照合。
- OpenCASCADE common体積とdistToShapeによる0°〜90°の91標本、159対/角度=14,469対。固定部材の276対も別検査。
- 体積許容差0.0001mm³。線形の最大貫通深さは算出していない。幾何学的接触と不正な貫通を分ける。
- この標本間の全経路についてはUNKNOWN。試料角度での非干渉を全経路へ一般化しない。Webでも未検査角度を区別する。
- 別の基準形状回転との27回の往復/反転姿勢比較、6件のnative負対照。保存した修正前FCStdで軸への誤貫通を再現し、修正後と比較。
- Blender実起動/background、blendとGLBの再読込、0/45/90/0のキーフレームと部材座標照合。
- Native TechDrawの軸半径・軸受穴半径は実際の円エッジへ参照。角度寸法は上下限変更90°→50°へ連動し保存再読込。軸受詳細は2:1、全体図は1:16.667。Web用投影とnative TechDrawを同一物として扱わない。

## 再生成とCIの区別

FreeCAD・PySide2・TechDraw、Blenderのある環境で、既存出力と異なる新しい出力ディレクトリを指定する。

```
TMPDIR=/path/to/workspace/tmp python3 cad/stage3b/run.py /path/to/new-output
python3 cad/stage3b/check.py
python3 cad/stage3b/check_test.py
node --test
node scripts/build-stage3b-site.mjs
node scripts/stage3b-browser.mjs
```

`run.py` は新規ディレクトリへCAD→干渉検査→図面→native反例→角度範囲変更→Blenderの順で出力する。標準チェックはリポジトリ内の固定成果を照合する。CIのportable検査は保存原本・hash・参照・原票の整合検査であり、CI内でFreeCAD GUIを再実行したとは主張しない。最終HEAD/CI/独立原証拠照合結果は最終報告に記載する。

## 独立照合とローカルWeb試験

独立担当は0.1/0.125/0.25/0.5°および89.5/89.75/89.9°など接触付近も細分化し、計15姿勢でBRep距離・交差体積を記録した。`evidence/stage3b/independent-native.json` を参照。これは追加標本であり、連続経路証明ではない。

最終ローカルWebは16構成と26故障条件で成功。選択可能な図面はhash照合したSTEP由来メッシュの投影であり、native TechDrawと別である。通常/減速、表示と停止、反転、CAD角度との実描画境界、3方向投影、部材選択、木柵接続、画面外停止を確認した。独立担当は原PNG/traceを照合し、新規ブラウザ操作でも再確認した。

初期実行ではGPU/target crash、固定時間待機や画面外判定に関する失敗を記録した。投影のキャッシュ化と、IntersectionObserverに加え画面座標/scroll/resize/フレームごとの停止確認を実装して、同じ操作を再検証した。GPU中断全体の原因を確定したとはしない。既存mainのローカルWPE回帰でもtarget crashが発生したが、それだけで新規変更と無関係と断定しない。最終CIの回帰結果と分けて記録する。

詳細な指摘・反例・限界は `independent-review.md` を参照。ローカルWebの原票は変更中の作業ツリーを明示しており、提出HEADのCIと同一と偽らない。提出後のCIで最終HEAD/treeを改めて照合する。
