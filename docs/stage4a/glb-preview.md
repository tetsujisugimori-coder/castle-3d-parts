# Stage 4-A 第2便・GLB配置増分（Refs #49 / PR #50）
第1便の固定カタログとv2保存契約を使用。木柵 PAL-U01（B0）の全14メッシュからU01の7つだけを抽出し、木戸 GATE-SIMPLE-01（固定B0）の7メッシュを使用する。GLB原本の複製追加はしない。木戸のGLB内改訂識別子は GATE-SIMPLE-01/B0、木柵は B0。
## 非公開の開発プレビュー
チェックアウトしたリポジトリのルートで `python -m http.server 8000 --bind 127.0.0.1` を実行し、`http://127.0.0.1:8000/previews/stage4a/preview.html` を開く。固定Three.js 0.180.0 CDNへの接続が必要。既存site/やPagesのビルドには含めない。これは閲覧試作であり組立編集画面・展示室導線は次工程。
## 照合と制限
- GLB実バイトSHA-256、manifestのID/版/姿勢/ノード、GLBヘッダー・内部リソース・ノードメタデータ・実ロード後のメッシュ境界を検査。境界比較は既存の1e-4 m許容差。
- 既存GLBはY-up。CADの配置座標(x,y,z)を(x,z,-y)へ一度だけ変換し、CAD Z回転をThree.js Y回転へ写す。3インスタンスを独立したGroupに配置し、頂点へ再変換をかけない。ジオメトリとマテリアルは同じ所有者内で読み取り専用共有。シーンから外した後で所有者をdisposeする。
- F01/G01/F02の21メッシュ・2接続点を検査。接続点の可視化は緑球であり模型の物理部品ではない。接続点の数学的照合は1e-9 m。GLB境界許容差とは別の判定。
- 旧応答は表示しない。読込/検証失敗時は前回有効モデルを保持する実装。WebGL喪失時は再読込みを要求する。実ブラウザでの故障対照は今後の検証対象。
